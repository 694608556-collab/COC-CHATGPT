# Windows Android production-kernel differential

Run from `mobile` with existing locked dependencies, Node, Android NDK
28.2.13676358, CMake 3.22.1/Ninja and platform tools. The runner downloads no
dependencies. SDK/tool paths can be supplied with parameters; `Get-Help
./scripts/check-table-kernel-android.ps1 -Full` lists them.

```powershell
# ANDROID_HOME (or ANDROID_SDK_ROOT) points to the existing SDK.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-table-kernel-android.ps1 -CompileOnly

# Requires one authorized device supporting both 64-bit and 32-bit ARM.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-table-kernel-android.ps1

# Dependency-free runner regressions; no device or compiler is accessed.
powershell -NoProfile -ExecutionPolicy Bypass -File tests/check-table-kernel-android.tests.ps1
```

The runner references the production `native/table-kernel/CMakeLists.txt` target,
including the same vendored Expat source and compile definitions/options. It
builds `tests/table-kernel-cli.cpp` for `arm64-v8a` and `armeabi-v7a`, using static
libc++ and Android API 23. The original 33 character cases and all 38 records
cases are generated by the existing complete-reader differential harness.

Device mode checks the ABI list before writing anything. Multiple transports,
including offline or unauthorized devices, require explicit `-DeviceSerial`
selection. Serial values and raw adb output are neither printed nor logged.
Every device write is beneath a freshly created
`/data/local/tmp/coc-table-kernel-<random-run-id>` directory; the runner neither
installs nor starts apps. Public inputs, probes and outputs remain in that
directory for diagnosis. The runner performs no remote or local recursive
cleanup.

Each ABI executes every case individually; records cases invoke the CLI with
the `records` argument. A nonzero compiler, adb, CLI or verifier exit stops the
run. After pulling all result JSON files, the runner invokes the existing
`check-table-kernel.mjs --saved-results` checker for each ABI. It also requires
both summary objects with `passed:true`, `nativeDifferential:true`, and exactly
33 and 38 cases. A JavaScript-only baseline cannot satisfy this gate.

Each attempt writes to a new directory under
`android/build/table-kernel-device` (override with `-OutputRoot`). Build and
verification logs, the public corpus, both executable hashes, and the final
`summary.json` remain local. The final summary exists only when the requested
mode finishes successfully; partial output from a failed attempt is not a pass.
`-CompileOnly` never calls adb, produces `status:"compiled-only"` with
`nativeDifferential:false`, and is only compilation/baseline evidence.

Passing these public differentials establishes production C-core equivalence
for this corpus on both ABIs. Android instrumentation, complete app builds,
real-table performance, private inputs, Swift and iPhone acceptance remain
separate required gates.
