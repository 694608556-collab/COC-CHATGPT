# 2026-10-21 全能签系统外部目录：Open无响应

## 用户确认与优先级

用户本次明确：全能签安装后能打开系统目录选择器，但点击右上角“打开/Open”没有反应。当前没有补报具体build、目录提供器或签名后应用标识，不从旧build34的反馈推断本次一定使用相同版本。仅“使用本机归档文件夹”有可用反馈，外部目录问题尚未修复。

Android上滑/后台化行为已按用户决定关闭优化，不修改手势实现。本问题为当前优先项；容量方向和64MiB现有限制保持。

## 当前证据及边界

- 本次需求决定已先推送：iOS f60123f、Android 04c1caa；此前差量开发和验证均已上传。交付安装包仍1.0.8/build48，没有替换旧包或发布新版本。
- 当前Windows没有检测到USB连接的iPhone。本机仅找到早期个人签名IPA，未找到出现问题的全能签成品，不能做同版本的有效签名对照。
- 已在仓库外独立Python环境准备pymobiledevice3 11.41.2只读采集器。实际预检输出为`NO_USB_DEVICE`、`usb_count:0`；命令及导入可运行，不代表设备信任或日志通道已验证。
- 采集器只枚举USB、复用已有信任并有界读取syslog；不自动配对、不安装/卸载应用、不操控屏幕、不修改归档或业务库。原始日志可能含私人路径，全部留仓库外，终端仅输出状态及计数，不上传。
- 已准备按diagnosing-bugs的HITL模板改写的Windows人工操作流程，人工结果与系统日志分别记录。尚未执行全能签设备复现，尚无能在该环境实际变红的反馈循环，因此不推断签名权限、提供器或应用回调为根因，不按猜测修改业务代码。

## 下一次复现

1. 先只做USB预检；成功后再确认已有信任和syslog服务可读。电脑不需要能够控制手机，手机上的点击由用户完成。不能连接、未信任或日志通道不可用都属于采集障碍，不算应用故障复现。
2. 沿用出现问题的应用与同一目录，在选择器中停在Open之前，不卸载、清库、重签名或改选本机入口。启动最多60秒的采集，确认READY后手机上点Open一次、等待10秒。
3. 分别记录：选择器是否仍在、是否返回应用、是否有可见错误、是否确认了保存位置。若意外成功，停止重复尝试并保留结果；不为了对照改写私人归档。
4. 相关原始日志只在本机分析；没有相关日志不等于证明应用没有收到回调。若系统日志不足以区分回调前后，再准备最小、脱敏的应用阶段探针，并在原环境复验。不得以模拟器正常或本机归档可用关闭此问题。

已准备的采集工具和人工流程均在仓库外；这份公开文档不包含设备标识、个人路径、签名材料或原始日志。实际设备复现与修复仍待完成。
