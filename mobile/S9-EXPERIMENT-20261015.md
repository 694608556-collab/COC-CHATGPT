## 真实发现：0.2.15 的小整数版本正文读取失败

实际点击已保存场次时提示“正文读取失败；原数据未改变。”，原生日志显示版本检查在正文投影之前拒绝。此时真实版本与请求均为 125，数据并未陈旧。

原因是新增 `getRecordContent` 使用 `PluginCall.getLong("expectedRevision")`。本工程所用 Capacitor 的实现只接受已装箱的 Java `Long`；普通 JS 小整数被 JSON 解析成 `Integer`，该方法返回 null。其他保存接口早已使用 `call.getData().getLong(...)`，因而模组保存正常，不能以保存通过推断阅读也通过。

修复只将这个版本读取对齐现有接口，仍检查是否提供版本、提交前后是否一致；不绕过 CAS、不减少正文、不修改数据库结构。版本递增到 19 避免与已经发现问题的 18 混淆。

浏览器 IndexedDB 模拟和纯 JVM 投影检查不执行 Capacitor `PluginCall`，因此没有捕获该类型差异。以后修改桥接读取必须保留实际设备读取回归，不能只跑这两类检查。
