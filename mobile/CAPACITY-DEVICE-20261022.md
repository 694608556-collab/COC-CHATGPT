# 按手机可用空间增长的整库容量

## 2026-10-22 动态容量与分段正文搜索：APK52/IPA50最终交付

Android 1.0.8/build52 与 iOS 1.0.8/build50 源码已启用按实际可用空间增长的整库存储，不再把64MiB作为整库产品总量。本次交付升级为APK52/IPA50；安装包通过核验，尚未在用户实体手机安装或计时。

### 用户可见行为

- 可继续增加场次及完整正文；数据与正文、数据库实际文件/日志占用、当前手机可用空间显示在“数据与设置”。MB/GB按十进制显示。
- 保存、批量检测、完整JSON/ZIP备份和恢复按用途核对真实存储卷可用空间，保留至少64MiB或当前空闲量5%的余量，并估算候选、SQLite页/日志及发布副本。空间查询不是磁盘预留，实际写入仍可能失败，必须保留事务和回读保护。
- 单场完整记录的元数据、rawContent、manualContent合计仍最多64MiB；元数据、单次编辑/表格、正文响应和普通附件保持独立预算。整库增长不自动放大每个请求、TXT/PDF或附件。
- 完整备份/恢复逐场处理，桥接片段256KiB；正文不集中送到界面。iOS底层本地文件默认整份Data读取，已改为顺序256KiB Range并核对206、区间、长度和全文件SHA-256，不做整份回退。Android本地文件使用原生InputStream响应流。
- ZIP保留独立的附件64MiB/个、128MiB合计、1999附件/2000条目限制，完整验证路径、重复名、CRC、目录/描述符、摘要及膨胀预算。ZIP32超过4GiB时明确拒绝，使用完整JSON；这不是新的整库数据限制。
- 预览只建立私有租约，不自动覆盖。明确确认后复查授权、保存位置、来源和候选证明、完整关联及CAS，在一个事务中全成或全败。候选删除失败时先拒绝提交；本次新附件发生补偿清理失败时明确报告保留，不删除既有文件。
- 自动备份沿用周期、修改判断和十份保留规则；完成新备份前不提前删除旧备份，不新增操作前副本。
- 模组正文搜索使用绑定当前revision的原生只读租约，逐场读取完整来源，只返回命中场次、数量与摘要；该租约不能暂存、恢复或发布文件，也不要求外部归档目录授权。来源摘要、选中场次覆盖及最终revision均验证，取消或查询切换后释放租约，旧查询不能覆盖新结果。
- 阅读按需加载所选场次，切换或关闭阅读时释放不再使用的正文缓存；SQLite完整正文保持原样，再次打开时重新读取。该行为避免随着阅读场次增加，把整库正文累计留在界面内存。

### 旧库与正文

Android以SQLite版本5标记新适配器，保留原v4索引和正文块；iOS以版本2加入事务式字节索引，保留原v1 metadata/body列和revision。排序、设置等元数据修改不读取或重写旧正文。iOS恢复和批量检测保留原始正文数值及转义词元，含超过JS安全整数的opaque raw字段；NUL及中文/emoji完整保存。

旧版适配器必须拒绝新数据库版本，避免用旧整库内存路径打开大库。不能以卸载或清空应用来降级或测试。
