# iOS 姓名候选与原生键盘：取证阶段

基线为交付 `9afde10`（IPA 应用源码 `801bc8a`，开发适配器 `648ae17`）。build46 云端运行 39448999303 attempt1 的 Public Beta 精确值断言观察到尾部空格；同源码 attempt2 通过。原因仍未确定，复跑通过不能作为修复证明。

## 本轮范围

在修改生产候选组件前补充可复现证据。原 `testPublicNameCandidatesWithNativeKeyboard` 的精确断言与 10 秒等待保留；新增两个独立启动复跑及六轮连续选择、重复选择同一候选、候选切换、职业/姓名焦点变化和键盘开关。保存后重启重新编辑，继续精确检查实际姓名。

原测试通过原生键盘创建模组 PC1/PC2，但没有检查这些源值。新增输入后与关闭键盘后的精确值检查及 Unicode 码点附件，以区分参与者输入已有空格、候选文本带空格、选择后输入事件改变值及保存时变化。断言失败保留原始值，不 trim、不延长超时、不调整系统自动更正设置。

事件跟踪只在 `DEBUG && targetEnvironment(simulator)` 且同时指定 `--coc-picker-ui` 和 `--coc-name-trace` 时安装。记录姓名/PC 输入的 beforeinput/input/composition、指针/点击、焦点、选择范围、可信事件标记、捕获/冒泡/微任务/帧后实际值，以及系统键盘通知。观察原生模组/角色提交的姓名和启动概览的已保存姓名，不记录正文。Release、实体机及 Android 不安装此跟踪器。跟踪本身可能影响事件时序，后续仍须无跟踪复验及实体机验收。

CI 即使失败也从当前新建模拟器容器导出 `ios-name-events.jsonl`，保留 XCTest 文本附件、完整日志和 xcresult。缺失跟踪证据单独报告，不能以 UI 通过推断有完整取证。

## 开发与安全

公司电脑旧工作区保留原状；变更文件、未跟踪文件、暂存/未暂存补丁和索引保存在仓库外 `preserved-local-20261021-verified`，每个文件核对 SHA256。本轮使用独立克隆目录，不恢复家中保护引用，不覆盖旧包，不操作生产应用。

本轮尚未修改 `NameSuggest`，未宣称根因确定或问题已修复。大库小改动差量、7秒确认分段计时、实体 iPhone/企业签名及正式 APK 覆盖升级仍待后续推进；64MiB、授权、revision/CAS、事务、自动备份规则和平台存储差异保留。
