### 性能结果及未完成项

降频本身没有解决全部卡顿：初始原生大样本设置/窗口内编辑调用仍约 7.1 秒。隔离诊断 APK 的定向阶段计时证明大量时间花在重复 JSON 解析/序列化；不是全归因于副本文件。最终删除该临时插桩，改为结构比较避免两次全量序列化，已解析/严格校验的完整请求保留原 JSON 文本，只有原生列表动作重新序列化。额外使用 Android JsonReader 严格校验原文，不能依赖 JSONObject 的宽松语法，否则不得存原文；实体与版本验证不跳过。

## 批量删除契约

沿用现有 Capacitor Logbook.commitAction，而非新增推测的 HTTP endpoint。请求为 `{ action: { type: 'delete-records', ids: string[] }, expectedRevision: number }`，返回沿用 `{ revision, exportedAt, safetyBackup }`。

证据和实现位于 src/data/actions.ts、src/data/native.ts、src/dev/browser-port.ts 及 android/app/src/main/java/coc/logbook/LogbookActions.java / LogbookPlugin.java。所有 ID 须非空、唯一且仍存在，验证完才改变候选快照；仅 reorder 可跳过专属安全副本，批量删除不能跳过。保留原 CAS、完整副本读回与 SQLite 事务。测试开发存储不进入 APK 入口，无请求/响应占位字段或临时生产日志。
