# 2026-10-18：S9 导出故障边界与最终收尾

接续 `dd9c78a` 和 [前轮完整矩阵](EXPORT-CONTINUATION-20261018.md)。正式 `coc.logbook` 1.0.3 / 28 及其数据、授权不操作；仅使用独立验证包和已选测试目录。私人正文、链接、设备标识、验证脚本、APK 与逐场证据均保存在仓库外。

## 本轮发现与修复

最终 SAF 保存期间强停的真机复现先失败：64 MiB 公开样本在约 17 MB 时观测到正在写入，终止后残留约 23.9 MB 的未登记文件，重开不能清理。业务 JSON/revision/旧登记不变，失败样本已保存到仓库外；只在确认它是本次专用测试文件且内容仍完全是已知样本后移除。

新增 `ArchivePublication`，将未完成发布记录保存在既有归档索引的私有 metadata 中，固定关联本次新建 URI、目录、完整大小和 SHA-256。封存来源在 `files/archive-publications` 固定一份私有引用，优先硬链接，文件系统不支持时复制；它不是操作前业务副本，也不写业务数据库或 revision。最多四份未完成/在途发布，避免失败材料无限增长。

直接小文件、分段文本/PDF 和自动备份复用同一发布边界：先检查版本已有的目录授权、新建唯一文件，持久记录后才写入；完整回读和再次检查当前目录/读写授权后登记。登记成功后先清除恢复记录，再释放私有引用。页面重建共享进程内在途标识，不能把另一页面仍在写出的文件误作残留；在记录持久化期间触发另一恢复者的竞态回归先失败后修复。

成功登记与删除对应未完成记录在同一个归档索引事务提交，既避免两者之间的中断状态，也减少每份文件一次同步写盘；之后的私有证明释放不再发起重复写事务。业务数据库和 CAS 不参与这一文件登记事务，仍保持独立。

下次对相同目录保存时，仅核对记录中的确切 URI。已登记文件只释放恢复记录，不删除；未登记文件必须仍与私有完整输出的字节前缀一致，才清理本次文件。被修改、缺少读取权限、提供器失败或系统拒绝删除时保留文件和证明，明确失败，允许恢复权限后重试。其他旧位置的未完成记录不会阻塞新授权位置，私有引用仍保留且受数量上限保护。不会遍历其他文件内容或清理旧归档。

Android 9 另有兼容问题：用户已移除未完成文件时，树 URI 的子项校验直接抛异常，不能当作普通空游标。现在先确认所属目录可读，再仅以该目录条目的精确 document ID 确认缺失；权限错误或提供器无法列举仍保留记录，不能把未知错误视为删除成功。

## 已完成的真机故障验证

- 发布中强停复现修复后通过：约 21.5 MB 残留在重开/下一次导出时清理，未登记文件消失，业务与旧登记相同。
- 发布前实际撤销测试目录全部持久读写授权：状态无效、发布拒绝、没有新登记；重新授予同一目录后保存成功。
- 写出中实际撤销写授权、保留读授权：完整输出可能继续经已打开的句柄写完，但最终再次授权检查拒绝登记。系统拒绝清理时保留 64 MiB 未登记文件及一份私有证明，未授权重试也拒绝。重新授权并终止/重开应用后，持久记录清理该失败文件，释放证明，随后重新保存成功；业务及旧登记不变。
- 外部修改未完成文件时拒绝自动删除；随后该测试文件被手动移除，Android 9 的旧 URI 校验异常先导致重试失败，精确 ID 核对修复后完整复现转为通过，业务和旧登记相同。

撤销授权使用只存在于仓库外隔离包的诊断 Activity，严格检查独立包名和测试目录。该入口、Manifest 和源文件不进入仓库，也不保留在最终干净验证 APK。

## S9 自身读取器检查

S9 / Android 9 的系统 `PdfRenderer` 实际从 SAF 成品打开 2,110 页 PDF，首/中/末页成功渲染并复看中文、英文、分页和首尾，无空白页或截断；不是浏览器替代结果。此前 78 份 PDF/4,445 页的完整可见字形序列及映射限制继续有效，不据抽样渲染声称逐页人工验收或复制文本逐字符一致。

Android 自身 `ZipInputStream` 完整读取合成 DOCX（22 部件）、XLSX（10 部件）及有界正文 ZIP（2 部件），CRC 和预期关键部件均通过。它证明 Android 可读的容器结构，不扩大为各第三方 Office 应用的版式验收。

## 保护、检查与范围

74 项单元、类型、格式及既有原生检查通过；新增 JVM 专项覆盖中断前缀清理、活动任务排除、已登记/已修改文件保留、删除失败后的证明留存与重试、空文件、其他目录、记录清理失败和跨页面竞态。另有确定性双线程回归先失败：回收者取得旧记录快照后，另一页面新建且失败的发布证明被误判为孤立文件；改为进程共享的所有权锁，记录创建、释放和证明回收共同串行，实际外部文件复制仍在锁外。修复后该回归通过，不会串行阻塞自动备份与导出的大文件 I/O。隔离包构建通过，最终去除诊断入口后还会进行六格式速度/成品回归。

恢复材料现在必须一起保存 `databases`、`shared_prefs` 和 `files`，尤其是未完成发布时的 `files/archive-publications`；不能只还原归档索引而丢弃相应私有证明。无未完成任务时该目录为空。旧 APK 不识别这些恢复记录，回退前必须先处理或保护它们，不清库或直接降级。

物理拔卡/全卷卸载会影响正式版也可访问的同一存储卡，不在“仅操作独立应用与专用目录”的范围内；本轮不执行。实际目录授权丢失、写入/删除被系统拒绝和生成/发布期间进程中断分别验证，不相互冒充。其他机型和第三方阅读器为后续兼容性范围，不能泛化 S9 结论。

提供器创建新文档返回到私有记录持久化之间仍存在无法跨进程原子提交的极短窗口；不承诺任意强杀/断电时所有提供器都绝无零字节遗留。恢复只删除有确切所有权与内容证明的文件，不能为消除这项限制去猜测或删除旧用户文件。代码阶段上传不代表未完成的最终检查已经通过。
