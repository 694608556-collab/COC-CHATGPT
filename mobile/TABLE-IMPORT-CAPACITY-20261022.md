# 2026-10-22 表格导入按设备资源处理

用户明确要求：不假定团数或场次数，不以单场完整正文、表格总文件大小、工作表总数、单元格总数或整库场次数设置产品上限。此次接续在 APK52 / IPA50 动态整库基础上实现 Excel / CSV 导入；新版本为 Android build53、iOS build51，安装包及最终验收状态以发布记录为准。

## 实现与范围

正式原生入口使用 tableStreamVersion=1。系统选择文件后分段复制到本次私有目录，核对完整长度与 SHA-256，按真实存储卷可用空间、暂存/事务副本及安全余量分配本次处理预算。不会把整份表格编码成 Base64 通过原生桥传递。

CSV 按行处理；XLSX 按 ZIP 中央目录、局部头、描述符、CRC、解压长度及完整来源摘要验证。ZIP64 可在系统精确数值范围内读取。共享字符串和目录证明保存在私有 SQLite 索引；正文逐行生成，最大 256KiB 分段并等待原生写入确认。工作表按实际 ZIP 顺序读取，候选按工作簿中的工作表序号和行号排序，保持原有导入顺序。没有旧的 20MiB 文件、100 工作表、200000 矩形单元格限制；稀疏单元格按实际坐标处理。

正式界面只接收最多100条名称/提醒，翻页替换当前页。确认前仅写私有暂存。确认后重新检查来源、候选、索引、当前目录授权和版本，单个事务提交新增场次及明确手动正文更新；失败整体回滚，已有在线正文不重新读取或改写。取消和清理仅作用于本次租约。自动备份与只读搜索不会在待确认表格预览期间抢占租约。

七版人物卡入口也改用分段 XLSX 读取，保留原专用模板、已保存公式结果、错误单元格与待补填提示；只收集该模板使用的“人物卡”范围，不执行公式。旧 XLS 格式保留 SheetJS 兼容路径，已取消人为文件总量限制，但该旧格式解析仍需较多运行内存。

元数据概览、完整备份解析/恢复不再因累计元数据超过64MiB而拒绝。搜索/批量等相关原生入口同步移除固定50000目标数量门槛。单次完整请求与单场正文的固定64MiB门槛已在本轮源码移除（原生完整验收中）；异常结构和无效来源继续拒绝，不能把预览或去正文元数据当作完整覆盖候选。

## 资源和兼容性说明

可用存储空间与运行内存是两种资源。大表格需要临时文件、SQLite事务及最终库的空间；保留动态空间余量，实际I/O失败仍应回滚。当前概览、实体关联校验和部分工作簿路径信息仍占用随实体数量增长的运行内存，旧 XLS 也有整份解析。因此不能声称“存储剩余足够就保证任意文件都成功”，也不能把主机Node堆限制当作手机总内存或实机能力。

此前保留单场元数据加完整 raw/manual 正文64MiB边界是范围理解错误；用户已明确要求移除，当前尚待最终端到端验收。文件损坏、格式不支持、缺少权限、来源变化或空间不足都必须明确失败，不截断正文、不静默跳过超大数据来显示成功。

CSV数值/日期、表头、正文续列、说明行结束、同模组参与者合并、来源去重及同名手动更新保持既有语义。XLSX非BMP数字字符实体按Unicode正确解码，修复旧SheetJS把部分字符截断的问题；缺缓存公式保留实际公式节点，七版待补填提示可更准确地说明原因。

## 验证口径

共享解析、候选摘要、取消、分页、CAS、权限失效、空间不足、事务回滚和旧正文保护均需测试。公开规模样本与实际原生仪器结果分别记录，正式发布必须等当前源码的两端完整云端验收与包内资源/身份/摘要核验。

本轮没有连接用户手机，不代表已安装或完成114场正式界面联网计时。Android先前Worker/编码优化和iOS网络会话复用继续保留；不能把表格导入规模测试描述为联网检测提速。

## 单场固定上限取消与验证进度

本轮源码现已移除上述固定内容门槛，共享capacity与两端原生Limits仅保留有界传输分段。Android正式正文继续分块，表格私有索引的SST/候选/手动正文/预览也改为256KiB块；iOS新增内部SQLite v3分块存储，原v1/v2正文在迁移中不改写，块有完整长度/SHA证明。迁移与后续写入保留同一事务，旧适配器不能读取v3，不以卸载清库测试。ZIP备份改为ZIP64并验证完整中央目录、本地头、描述符、CRC和全文件SHA；取消待处理写入结束后才释放本次租约。

本地类型、Android177/iOS171单元、两端生产资源核验通过；公开单场70MiB已走CSV候选、JSON/ZIP64备份与恢复候选、完整编辑上传并核对全文摘要，证据为tests/evidence/single-record-scale-20261022.json。该多阶段桌面脚本峰值RSS约1.40GiB，不是手机指标或新的内容配额。ZIP测试完整往返65536成员及超过4MiB中央目录；>4GiB长度/偏移使用格式字段边界测试，不冒充实写4GiB文件。原生大单场、完整浏览器与云端结果仍待最终记录，尚未交付新包。

ZIP64格式依据：[PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。这是格式兼容依据；容量与完整性结论以本仓实际测试为准。
