# 公司电脑接续：0.2.13-dev / versionCode 16

接续 `codex/android-browser-edit` 的 `a858e02b7a57d3a14c3242400a5126c6f80e5d02`（0.2.12-dev / 15）。本轮只修改手机三个模块及相关存储、测试和记录。公司没有安卓手机。

## 已完成

- 本机旧提交和旧工作文件、找到的桌面应用数据及 localhost 浏览器存储已在仓库外保护，未重置原有工作副本。新目录取得全部分支历史及完整源码，含共享代码和八个原字体；没有将旧本地提交覆盖到当前分支。历史桌面安装包/视频的 LFS 二进制未用于手机开发。
- 在完整仓库的 `mobile` 执行 `pnpm install --frozen-lockfile`、`pnpm dev`，预览仍为 <http://127.0.0.1:4173/>，仅监听本机。
- 场次编辑草稿和每次输入的脏检查不再克隆、编码未改在线正文。保存角色／场次使用 `commitEntity({edit, expectedRevision})` 单实体请求；校验角色完整字段、关联及场次来源。未改正文保留引用，提交失败保留草稿及旧快照。
- 原生角色编辑仅更新角色、参与者关联和时间。场次编辑使用小 `recordValues` 覆盖；未变来源保留原在线正文，变更来源清除旧正文；再改回旧链接也不能复活底层旧正文。手动正文仍完整保存。
- 删除／批量删除只校验元数据，先验证全部目标再一次事务记录删除；未选正文不解析、编码或重写。清空仍仅清模组、场次、角色，设置、授权和现有归档保留。排序仍立即保存当前顺序，涵盖新建、编辑、删除后的场次。
- 自动备份捕获确定的已提交 revision 和完整原始 JSON，再在独立线程写入、回读和轮换，不占用界面全局写入锁。仅备份按钮显示进行中，其他数据操作可继续；完成回调保留期间的新数据、版本及草稿。
- 自动备份记录 `lastAutoBackupRevision`，并发期间新修改不算已备份，同一毫秒的不同版本也能区分。默认十分钟、有修改才生成；每日／每周和手动立即生成保留。首次仍从修改时间起算，后续从成功时间起算。失败不标记已备份。
- 数据库内部版本 v3：v1 创建元数据表、v2 保留原表，均不替换原快照、正文块和 revision；新覆盖字段只在完整读取／导出／备份时组合，外部格式仍是 schemaVersion 2。版本提升使旧数据库 v2 APK 拒绝降级读取这些覆盖字段；不可安装旧 APK 回退，也不能清库代替迁移。
- 不恢复任何操作前副本规则，不删除已有 safety／手动文件。保留确认、输入校验、CAS、目录授权、SQLite 事务、失败回退和完整字体／正文。桌面版本说明原文不变。
