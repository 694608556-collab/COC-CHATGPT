114 场合计 74,457 条消息，网络响应 6,558,076 字节，完整规范正文 JSON 43,968,957 字节，上传候选 44,170,510 字节/218 段。每轮新建独立数据库，最终逐场核对完整正文 SHA-256；没有删减原始字段、消息、附件引用或摘要以换取速度。

## 已验证的开销与修改

1. 原先下载解析后的完整正文由 Worker 返回主线程，再传回 Worker 校验/准备上传，准备结果还携带完整快照。现在在同一 Worker 解析、完整校验并保留上传字节，只返回元数据及租约；进度仍在原生暂存成功后发布。最多三个响应槽位、一份活动上传字节，下载仍可重叠，上传逐场串行。
2. 旧 WebView 的大文本 UTF-8 编码开销明显。细分测量中一次输入编码累计 5.793 秒；改用 Worker 内 Blob + FileReaderSync 后为 1.745 秒，仍完整编码并执行同一 JSON/结构/关联校验及摘要计算。输出编码、响应摘要也沿用字节等价路径。
3. Base64 分段改用 Worker 系统读取器，主线程/Node 或不具备接口时保留原有实现。每段仍至多 256 KiB，完整上传仍不超过 64 MiB。读取错误明确失败，不以空白或截断内容继续。

[Blob 的 UTF-8/换行语义](https://developer.mozilla.org/en-US/docs/Web/API/Blob/Blob)与 [Worker FileReaderSync 字节读取](https://developer.mozilla.org/en-US/docs/Web/API/FileReaderSync/readAsArrayBuffer)作为接口依据；真正的字节一致性另由浏览器 Worker、S9 全量摘要及公开 Unicode 回归验证。

## 回归与保护

新增完整上传字节等价、失败元数据、失效关联拒绝、迟到解析失效、旧租约清理不释放新正文、Base64 视图范围/尾组/读取失败，以及 UTF-8 的 CRLF/BOM/NUL/emoji/孤立代理项回归。浏览器增加真实 Worker 的大正文逐字节上传检查。初次单元全量运行在大字节数组逐元素断言时超过五秒；改为完整 Buffer 字节相等比较后通过，没有减少输入或放宽业务断言。

初期诊断摘要预期直接使用解析器对象的 JSON 字段顺序，实际保存使用完整校验后的字段顺序，产生 114 项误差。预期修正为既有完整校验路径的序列化结果后，旧路径和新路径都逐场一致；未修改生产业务比较器。原生来源身份修复、完整来源/关联校验、授权、CAS、事务回滚、64 MiB、自动备份及平台差异保持。
