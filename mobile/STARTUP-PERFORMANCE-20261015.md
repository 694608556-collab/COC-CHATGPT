# 启动按需读取试验：0.2.15-dev / versionCode 18

用户反馈：每次关闭再打开，加载已有数据仍等待很久。基线为独立 UI 试验分支 `f280892`；该提交保留于 `codex/before-startup-optimization`，完整本机保护包为工作区外层 `preserved-local-20261015/before-startup-f280892.bundle`。原版、UI 试验一／二／三和应用数据均保留。本轮只优化手机三模块，不合并 PR、不正式发布。

## 原因与本轮变化

原冷启动串行执行：八个原字体加载 → getState 拼接全部正文并跨桥传输 → 创建／写入／回读／删除归档测试文件 → 工作线程解析并逐条校验全部消息 → 展示列表。即使用户只改设置或角色，也先付出全部正文的成本。

进程仍存活时的后台／前台切换，原本已调用 getStatus 检查 revision 和持久目录授权；保持这条轻量路径。彻底关闭后内存消失，重开仍必须恢复持久化元数据，不能把旧内存当作永久数据，也不会重新导入、重新抓取网络日志或重置用户设置。

本轮实现：

- 新增只读 `getOverview()`：返回全部模组、场次元数据、完整角色、设置、revision、持久授权状态和正文待取 ID；不传输 rawContent／manualContent，不调用写测试文件。授权选择时仍实际写入回读验证；实际导出、备份和事务的授权／失败保护保留。
- 正式入口将原字体加载与 getOverview 并行；仍等待全部原字体成功后渲染，不用系统字体替代。启动读取失败显示错误及显式重试，不自动清库。
- 新增只读 `getRecordContent({ids, expectedRevision})`：只返回明确所选场次的完整正文，读取前后检查 revision，缺失目标整批失败。前端工作线程执行原有完整结构／正文来源／业务关联校验，再核对批次、归属和版本；失败不合并任何部分。
- 阅读一场只取一场，模组正文搜索取该模组尚未读取的场次；同一次运行复用已读正文。搜索尚未取齐时不显示虚假的零结果，失败可重试，回车也可重试。
- 列表“正文已保存”及设置统计依据原生正文索引，不因延迟读取显示缺失。模组／角色／设置／排序／删除仍可走原有轻量事务，不要求先读取正文。
- 手动 JSON／ZIP 备份、表格导入追加、整表导出及现有全快照日志更新，先取齐尚未读取的正文，再走原有流程。完整提交入口额外拒绝尚未读齐的状态，避免把列表概览保存成空正文。确认恢复本来就是明确覆盖，使用完整已校验预览和当前设置，不需要先取将被覆盖的正文。
- 原生自动备份仍直接捕获 SQLite 当前完整版本，不依赖前端已加载多少正文；十分钟、有修改才生成及并行文件写入契约不变。
- 读取新概览成功后关闭旧场次详情，防止外部 revision 变化后继续把旧详情当作当前版本；未保存编辑仍沿用原先不自动覆盖的保护。
- 不修改 SQLite v3 的表结构、存储正文块、外部 schemaVersion 2 或已有归档；读取投影不会回写数据库。回滚源码不需要降库或清数据。

## 测量与验证边界

公开虚构样本：75 场、7,500 条消息、1 个角色。完整 JSON 为 6,313,868 UTF-8 字节，概览为 28,893 字节，启动界面载荷减少约 99.54%。专项浏览器拦截禁止 getState，确认重开、设置和角色编辑没有正文请求；第一次阅读第 75 场仅请求 `startup-74`，返回再开无新请求。

这些是桌面 Edge／开发 IndexedDB 边界的载荷与调用结果，**不是 Android 启动毫秒数或提速倍数**。开发端为模拟接口会先解析 IndexedDB 保存的 JSON，不能据此计算原生 SQLite 读取速度。原生只读投影另经 JVM 辅助类验证原始正文数字精度、Unicode、所选范围和不修改存储文本。

检查记录：

- 56 项单元检查通过，包括正文索引拒绝错误 ID、整批合并及失败保留。
- 33 项 Java 辅助类检查通过；不代替 Android 桥接、SQLite、SAF 验证。
- 最终 69 项完整浏览器流程通过（原有 66 项及新增 3 项）：大样本按需复用，部分／陈旧／失败结果拒绝并重试，表格追加及从未打开正文的完整备份。完整证据为本机忽略的 `evidence/startup-final-20261015`；Android 云端编译结果在本文件末尾补记。
- 类型、格式、ESLint、网页构建和 cap sync 通过。仅在隔离浏览器使用公开样本，没有操作用户预览里的业务数据。

## 仍待完成

- 当前 v3 底层首次 `fields()` 仍需读取、拼接并切片既有原始 JSON 正文文本；本轮避免了全正文跨桥、界面对象构造和逐条前端校验，不宣称磁盘只读元数据。若真机这段仍慢，再测量后考虑可重建的持久索引或逐场正文存储，不能用假缓存放弃一致性。
- 全快照日志更新／表格等路径会取齐正文；本轮没有将所有写入改为逐场存储。模组搜索第一次仍需读取整个模组，首次阅读仍有该场校验等待。
- 原字体加载、原生启动、SQLite 首次打开、完整大场次解析和真实归档 I/O 的分段耗时，须在同一手机／样本实际测量；不承诺“秒开”。
- S9 / Android 9 / WebView 78，以及 Mate 40 Pro / HarmonyOS 4.2、红米 K80 指定 OS、荣耀 90 / Android 15：均须保留数据升级后分别验证冷启动、热恢复、首次／重复阅读、搜索、完整备份及授权失败。公司没有安卓手机，不将浏览器或云端编译写成真机通过。
- 原拖动手感、v3 保留升级及真实卡 I/O 等历史待验项继续保留；不恢复删除功能、操作前副本或放大按钮。
