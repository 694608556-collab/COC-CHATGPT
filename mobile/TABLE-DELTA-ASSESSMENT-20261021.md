# 大库小改动：差量与计时评估

## 已测量的范围

`node scripts/profile-table-confirm.mjs single` 使用公开生成的350模组、7000在线+50手动场次元数据，只更新一场手动正文；`append` 使用50模组/1050旧场追加6000场，最终350模组/7050场。它调用真实 `importTable` 和完整 `previewBackup`，并逐轮与真实 `performSnapshotJob({type:'prepare'})` 的快照、JSON逐字对比。一次预热加五次测量，原始结果在 [公开验证目录](verification/name-investigation-20261021/)，构建目录也输出本次结果。

本机 Windows Node 的候选为2,424,345 UTF-8字节；假设差量只含一场手动更新及五个操作数组时为271字节。后者仅用于评估载荷，不含正式协议版本/预览令牌等开销，尚无差量写入实现。

| 主机阶段 | 五次中位数 |
| --- | ---: |
| structuredClone | 8.300 ms |
| 候选 JSON 编码 | 4.859 ms |
| UTF-8 编码 | 2.507 ms |
| UTF-8解码/JSON解析/完整结构及关联校验 | 9.187 ms |
| 校验后 JSON 编码 | 5.009 ms |
| 上述总和（逐轮总和取中位数） | 30.440 ms |

追加6000场时，完整候选2,575,752字节，差量示例仍为2,221,619字节（约减少13.7%）；上述主机阶段总和中位数29.773ms。大批量新增本身占载荷大部分，不能由单场更新的载荷缩减推断大批量也能获得同等比例收益。仍须在设备上区分真实桥接、原生校验和6000条SQL写入时间。

这里没有旧正文，也没有 WebView Worker 消息、原生桥接、目录授权、SQLite和设备I/O计时。不能把这些数字减去S9的3.769秒或6.973秒来归因，也不能宣称实机提速。不同阶段中位数相加不等于逐轮总时长的中位数。

## 两端实际路径

当前确认均再次把完整元数据候选发送到 Worker，执行 JSON编码→UTF-8→完整备份校验→JSON编码，再把全部JSON经 `commitTable` 送到原生。取消/预览不读取旧正文的契约不变。

Android `LogbookPlugin.commitTable` 先做完整流式校验，再JSON解析，事务中 `IndexedSnapshot.importTable` 读取全量旧元数据、检查候选约束、再按每条记录比较/写入。`TableImport.validate` 对未允许更改字段也会序列化复制元数据；`importTable` 又建立旧记录映射并解析比较。追加末尾已每事务仅计算一次，不应重复把它列为待修。容量保护使用现有正文长度索引。

iOS `LogbookMutations.table` 先完整校验候选并逐条比较旧元数据；`LogbookStore.mutate` 再完整校验合并元数据、逐条比较决定写入。原v1 `transaction` 还汇总metadata/body字节保证64MiB边界。这些是代码路径，尚无各阶段设备时间占比；不得直接移植Android v4索引或省略iOS容量检查。

## 建议的下一实现与验证顺序

1. 先为真实Worker任务、桥接和原生加单调时钟计时。界面记录投递前/响应后，Worker单独记录JSON/UTF-8/完整校验/编码，原生区分排队、解析校验、授权、读取元数据、候选关联校验、SQL写入、容量检查与事务提交。时间只在同一时钟域计算；总墙钟由调用端计量，差值只能称消息/排队等未分配时间。仅公开夹具收集，不记录正文、目录URI、设备标识或签名材料。
2. 新增可探测的 `commitTableDelta`，不改变既有 `commitTable` 含义。载荷仅有新增模组/角色/场次、明确变化的模组参与者、明确手动更新；不提供删除、重排、来源或其他旧字段的操作。预览revision与能力缺失时保留当前安全路径。
3. Worker可以保留绑定revision的不可变预览令牌；确认时对自身完整候选重新完整校验并导出差量，避免UI再次复制7050场候选。令牌失效、Worker重启或revision变化均拒绝，不接受UI伪造的“已校验”标志。原生仍以自身完整元数据应用操作后进行完整关联校验，不能只验证新增行。
4. 原目录/即时授权、预览revision、事务内CAS、64MiB全库容量与任何失败的整批回滚全部保留。新ID重复/冲突、未知操作/字段、非法角色关联、在线正文覆盖、手动空行/Unicode、取消、权限变化、SQL失败与重启均须先有回归。旧正文原始块/元数据逐字节及6000新增顺序保持验证。

先测量再改变原生循环或容量实现。差量能显著减少载荷，但完整关联校验和容量保护仍有全库成本，不能预先承诺小改动为常数时间或宣称消除了3.769秒。

## 无设备阶段：差量契约草案（待实现）

2026-10-21用户确认公司电脑目前没有可用测试设备。以下用于后续实现审查，当前安装包仍执行原commitTable；没有新增写库接口或实机提速结论。此前271字节是旧的载荷示例，不能直接当作本草案完整实体载荷的实际大小。

### 载荷与能力

建议新增明确的`tableDeltaVersion:1`能力声明和独立`commitTableDelta`，不以JavaScript代理方法“存在”判定原生能力。请求保留原expectedRevision，delta仅允许五种数组：

| 数组 | 内容和约束 |
| --- | --- |
| modulesAdded | 原预览新增模组的完整元数据，按原预览追加顺序 |
| moduleParticipants | 确实变化的已有模组完整元数据；仅kps/pairs可变化，其余字段须与原生旧值相同 |
| charactersAdded | 原预览新增角色的完整元数据，原角色不提供编辑操作 |
| recordsAdded | 原预览新增场次的完整元数据，明确新手动正文可附带；不得携带rawContent覆盖缓存 |
| manualUpdates | 原预览明确手动更新的完整场次元数据及manualContent；只允许原表格契约的正文、updatedAt、playDate、dateSource变化 |

变化实体携带完整元数据可保留缺失字段与显式空值的原语义，避免自行发明“省略即清空”的补丁规则。manualUpdates必须是原生已存在的manual场次，字段/来源和非导入属性按现有table约束检查；空行、Unicode、空字符串均保留原导入算法语义，不trim。所有数组、实体和跨操作ID重复、未知顶层字段/操作、非法类型或旧实体冒充新增均拒绝。没有删除、重排、设置更改、在线正文替换或通用任意字段更新操作。

已有设置全部由原生保留；首次空库的设置初始化需单独定义，只在原生确认尚无元数据时接受完整校验后的初始设置，保持现有平台默认值/首次导入语义。不能根据客户端“空库”标志或revision数字自行放行。提交时间仍由原生成功确认路径产生并返回；不能恢复用预览时间启动首次自动备份的旧问题。

能力缺失只在尚未发送差量写入前降级到当前完整元数据commitTable。发出写入后发生超时/通信失败，不自动改走另一写入接口：原生可能已提交而回复丢失。保持原revision进行结果核对/显式重试，CAS拒绝重复提交；重新读取元数据后再建立预览，不能默默换新revision重放旧操作。

### Worker预览持有与确认

Worker在完整importTable/previewBackup校验后保留一份不可变元数据候选和基线，返回绑定本次revision的预览标识。确认只发送标识及revision，Worker重新完整校验自己的候选，生成差量，并校验“把操作应用到原基线”与完整候选的实体顺序/元数据/明确正文逐项一致。UI提供的标识没有写库权力，也不能作为原生免校验凭据。

预览取消、成功、重新选文件或被新预览替代时释放；Worker重启/标识失效必须重新预览，不静默跳过完整校验。最多保留当前预览，确认在途禁止重复确认。不得为留存预览把旧正文读入Worker。第一阶段仍可返回已校验的完整元数据用于现有UI更新；减少一次UI到Worker复制和缩小原生桥接载荷，不据此声称已消除所有7050场元数据处理或副本。

### 原生应用及平台边界

原生首先核对能力版本、长度/UTF-8/JSON/实体类型和请求revision、原目录及即时授权。在原写事务和CAS保护下读取自身完整元数据，按白名单操作合并；保持旧数组前缀和原顺序、新实体按差量顺序追加，再对最终完整元数据做现有结构、唯一ID、来源和全部模组/角色/场次关联校验。不能只检查变化数组，也不能信任Worker声称“已通过”。目录与权限在事务内原边界再次核对。

Android继续v4正文块和长度索引，仅写新增/明确变化实体；iOS继续v1 body列和现有容量计算，不能套用Android数据库。全库旧正文仍保留在原生，未更新正文的原始存储词元保持不变；64MiB按最终完整资料库计算。SQL、容量、权限、摘要/结构或CAS失败整批回滚，不能先发布部分元数据或正文。取消不调用写入接口，不新增操作前副本或改变备份周期。

### 实施门槛

先建立原生端明确阶段计时，再比较完全相同的公开1050→7050追加场景及7050场单手动更新。每次同时保留总墙钟、Worker校验/编码、桥接往返、原生排队/校验/读取元数据/SQL/容量/提交阶段，时钟域分别计算；设备未连接时不填设备耗时。计时只记录阶段、数量、字节和耗时，不记录正文/目录URI/设备标识。

回归需先验证旧路径与delta重建结果等价，再覆盖重复/未知ID、旧实体伪新增、非法关联、在线缓存覆盖、非导入字段变更、顺序、首次空库、能力缺失、丢失回复、Worker重启、取消、授权/目录变化、旧revision、中途SQL/容量失败、手动空行/Unicode及进程重启。保留全部旧正文原始块/元数据和6000条新增顺序的逐项校验；通过这些检查前不切换生产确认路径。

### 完整变化实体的只读重建评估
