# 2026-10-17：原字体后台 PDF 提速（进行中，非正式 APK）

正式版仍为 `coc.logbook` 1.0.3 / 28；只升级授权的独立验证应用。实际链接、正文、测试目录及逐场证据留在仓库外。没有改业务数据库、字体资源、按钮尺寸、CAS、事务或备份规则。

## 已实现的生产路径

Android 将完整过滤文本按 256 KiB 写入有界私有输入，再由独立后台线程使用原 SF Pro Text / PingFang SC 排版 A4 PDF。浏览器仍用原逐页图像路径。原生状态区分排版、实际已绘页数、编码与最终发布；不再把整页转为图像。仅表情序列按原系统字体的实际字形绘成小图，避免 Android 9 为一个表情重复嵌入约 11 MB 的字体，不替换普通文字字体。

一个任务拥有输入/输出临时文件，UTF-8 严格解码，内存不足明确失败，输出仍限制 64 MiB（不是页数上限），不截断正文。完成才允许原有唯一新文件、流式复制、回读 SHA-256 和登记；取消、失败及已请求取消的 ready 状态均不得发布。私有临时文件清理、启动后下次导出清理上次残留；从不扫描或删除共享旧文件。

## S9 已测及范围

Android 9 / WebView 78，实际 76 场、24,487 条消息，先读取完整测试正文后计时，**不是 UI 点击起算**：

- 首个原生实现（仍嵌入表情字体）：76 份约 99.920s、249.4 MB；合成 2,110 页生成/保存约 23.747/0.826s、15.7 MB。
- 表情小图后，原 2 秒命名缓存/120ms 轮询：76 份约 75.300s、27.6 MB，全部成功，业务 JSON/revision 不变。公开单页表情样本 10.7 MB→0.186 MB，约 2.532→1.531s，中文、英文、表情和复杂文字已渲染复看。
- 后续 30 秒目录缓存和 32ms 轮询的联合候选：76 份约 56.067s、27.6 MB；此前 30 秒缓存/120ms 轮询为 62.609s。同样候选的 76 场合成 2,110 页约 24.100s（生成 23.494、保存 0.606），5.2 MB。数字不拼接成同一轮，不将未包括的冷读/UI 时间算作零；目录随测试增加，不是固定文件数基准。

原栅格基线 76 份约 782.085s / 2,143 页；原合成在排版 264.674s 时诊断停止，不是成功。新排版字体仍是原字体，但平台测宽与画布存在少量断行差别，不承诺每个分页位置一致。PDF 文字提取有旧系统字体 Unicode 映射/表情图形差异，不能宣称复制搜索与原始正文逐字符相同；完整备份/TXT/JSON 仍保留可编辑原文。实际新文件的全文、全部分页及 UI 点击矩阵仍在补验，不能据页数和首尾抽看宣布全部完成。

## 取消时发现的 Android 9 问题

初次原生写出取消时，Skia 吞掉 Java 输出流异常并反复重试，验证任务长时间不结束。只强停独立测试应用后恢复，正式版未动。新增有界 OS 适配回归先红，再改为取消/写入失败后停止写入并排空原生编码，退出 `writeTo` 后拒绝发布、清理私有文件，避免重试死循环。不能把这个失败记录删除或称初版已通过。

S9 修正后：排版取消约 176.8ms、绘制约 154.6ms，编码阶段约 5.060s；界面可响应，但原生编码不能立刻中断，所以最后阶段清理仍可能等数秒。三项取消及无效 UTF-8 失败后，业务 JSON/revision、全部旧登记不变，输入/输出缓存为空。尚需新界面状态、进程中断恢复、权限变化及重试的最终端到端覆盖。
